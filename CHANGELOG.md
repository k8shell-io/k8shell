### Upgrading from 26.11.2

- **Workspaces move to organization namespaces.** Standalone workspaces now run in a namespace per organization (`<workspace namespace>-<organization>`). Workspaces created by an earlier version keep running in the old shared namespace but are no longer listed or managed, and the provisioner warns about them at startup; there is no migration. Save what users need from those workspaces and recreate them after the upgrade.
- **Organization limits without a license.** An installation without a license is limited in organizations, users per organization and workspaces per organization. If it already holds more than the limits allow, nothing new can be created after the upgrade until it is back within them or a license is uploaded in the console.

### Features

- **GPU workspaces**: blueprints can request whole GPUs or slices of GPU memory and cores; the provisioner maps them to the cluster's GPU resources, tolerations and node selectors, and GPU support stays off until configured. ([provisioner@33a2c27](https://github.com/k8shell-io/provisioner/commit/33a2c27), [provisioner@32ec6d2](https://github.com/k8shell-io/provisioner/commit/32ec6d2), [charts@df16322](https://github.com/k8shell-io/charts/commit/df16322))
- **Node pools show their GPUs**: for each GPU pool, the GPU models and memory sizes it offers, with the number of cards and of shareable slices. ([#2](https://github.com/k8shell-io/k8shell/issues/2), [api-server#93](https://github.com/k8shell-io/api-server/pull/93), [frontend#91](https://github.com/k8shell-io/frontend/pull/91), [provisioner#67](https://github.com/k8shell-io/provisioner/pull/67), [provisioner#68](https://github.com/k8shell-io/provisioner/pull/68))
- **Node pools show CPU and memory capacity**: allocatable CPU and memory of every pool, in total and on the nodes that can take workspaces. ([#4](https://github.com/k8shell-io/k8shell/issues/4), [api-server#95](https://github.com/k8shell-io/api-server/pull/95), [frontend#93](https://github.com/k8shell-io/frontend/pull/93), [provisioner#69](https://github.com/k8shell-io/provisioner/pull/69))
- **GPU usage in workspaces**: utilization, memory, temperature and power of a workspace's GPU in `kbox info` and in the workspace's performance view. ([#3](https://github.com/k8shell-io/k8shell/issues/3), [api-server#94](https://github.com/k8shell-io/api-server/pull/94), [frontend#92](https://github.com/k8shell-io/frontend/pull/92), [charts#15](https://github.com/k8shell-io/charts/pull/15), [k8shelld#73](https://github.com/k8shell-io/k8shelld/pull/73))
- **Node usage page**: Performance → Usage shows per node what workspaces request, are limited to and use, so overcommit and busy nodes stand out; off by default (`provisioner.nodeUsage.enabled`), with only the cluster permissions the enabled parts need. ([#5](https://github.com/k8shell-io/k8shell/issues/5), [api-server#98](https://github.com/k8shell-io/api-server/pull/98), [frontend#94](https://github.com/k8shell-io/frontend/pull/94), [provisioner#73](https://github.com/k8shell-io/provisioner/pull/73), [charts#16](https://github.com/k8shell-io/charts/pull/16))
- **GPU usage and waiting workspaces on the usage page**: GPU capacity, reservations and (optionally) utilization per node, and the queue of workspaces waiting for resources. ([#7](https://github.com/k8shell-io/k8shell/issues/7), [api-server#99](https://github.com/k8shell-io/api-server/pull/99), [frontend#95](https://github.com/k8shell-io/frontend/pull/95), [provisioner#75](https://github.com/k8shell-io/provisioner/pull/75), [charts#18](https://github.com/k8shell-io/charts/pull/18))
- **A namespace per organization, with quotas**: every organization's workspaces run in their own namespace, and admins can cap an organization's CPU, memory and GPU use with a quota. ([#8](https://github.com/k8shell-io/k8shell/issues/8), [api-server#100](https://github.com/k8shell-io/api-server/pull/100), [frontend#96](https://github.com/k8shell-io/frontend/pull/96), [identity#50](https://github.com/k8shell-io/identity/pull/50), [provisioner#77](https://github.com/k8shell-io/provisioner/pull/77), [charts#19](https://github.com/k8shell-io/charts/pull/19))
- **Usage limits without a license**: installations without a license are limited in organizations, users per organization and workspaces per organization; uploading a license in the console lifts the limits. ([api-server#103](https://github.com/k8shell-io/api-server/pull/103), [frontend#99](https://github.com/k8shell-io/frontend/pull/99), [identity#54](https://github.com/k8shell-io/identity/pull/54), [provisioner#80](https://github.com/k8shell-io/provisioner/pull/80), [charts#30](https://github.com/k8shell-io/charts/pull/30))
- **Hot reload in injected development workspaces**: a workspace injected into a service's pod can swap the service binary and restart only the service process, with unchanged production images. ([#15](https://github.com/k8shell-io/k8shell/issues/15), [api-server#104](https://github.com/k8shell-io/api-server/pull/104), [authz#20](https://github.com/k8shell-io/authz/pull/20), [identity#55](https://github.com/k8shell-io/identity/pull/55), [idp-github#14](https://github.com/k8shell-io/idp-github/pull/14), [idp-google#4](https://github.com/k8shell-io/idp-google/pull/4), [provisioner#81](https://github.com/k8shell-io/provisioner/pull/81), [session#21](https://github.com/k8shell-io/session/pull/21), [ssh-proxy#39](https://github.com/k8shell-io/ssh-proxy/pull/39), [charts#32](https://github.com/k8shell-io/charts/pull/32), [k8shelld#76](https://github.com/k8shell-io/k8shelld/pull/76))
- **Quickstart for k8shell 2.x**: `curl -sSfL https://get.k8shell.io | bash` now installs the 2.x chart, picking the installation mode (full, without cluster RBAC, or namespace admin) from your Kubernetes permissions. ([#14](https://github.com/k8shell-io/k8shell/issues/14), [charts#28](https://github.com/k8shell-io/charts/pull/28))

### Enhancements

- **Blueprint editor**: GPU requests, CPU and memory overcommit (no longer dropped on save), runtime class and a new Schedule tab; workspaces show Warning and NodeLost statuses with their message. ([frontend@5f921e4](https://github.com/k8shell-io/frontend/commit/5f921e4))
- **Unschedulable workspaces explained**: a workspace whose pod can't be scheduled shows a warning with the scheduler's reason instead of waiting at "Starting". ([provisioner@792b88f](https://github.com/k8shell-io/provisioner/commit/792b88f))
- **Install without cluster-scoped RBAC**: the chart renders cluster roles only for the features that need them (organizations, node information), so it installs in clusters that allow only namespaced RBAC. ([#11](https://github.com/k8shell-io/k8shell/issues/11), [api-server#101](https://github.com/k8shell-io/api-server/pull/101), [frontend#97](https://github.com/k8shell-io/frontend/pull/97), [identity#52](https://github.com/k8shell-io/identity/pull/52), [provisioner#78](https://github.com/k8shell-io/provisioner/pull/78), [charts#25](https://github.com/k8shell-io/charts/pull/25))
- **arm64 images**: every service and k8shelld image is published for linux/amd64 and linux/arm64, so k8shell runs on arm64 clusters such as Apple Silicon Macs. ([#13](https://github.com/k8shell-io/k8shell/issues/13), [api-server#102](https://github.com/k8shell-io/api-server/pull/102), [authz#19](https://github.com/k8shell-io/authz/pull/19), [frontend#98](https://github.com/k8shell-io/frontend/pull/98), [identity#53](https://github.com/k8shell-io/identity/pull/53), [idp-github#13](https://github.com/k8shell-io/idp-github/pull/13), [idp-google#3](https://github.com/k8shell-io/idp-google/pull/3), [provisioner#79](https://github.com/k8shell-io/provisioner/pull/79), [session#19](https://github.com/k8shell-io/session/pull/19), [ssh-proxy#38](https://github.com/k8shell-io/ssh-proxy/pull/38), [charts#29](https://github.com/k8shell-io/charts/pull/29), [k8shelld#74](https://github.com/k8shell-io/k8shelld/pull/74))
- **SSH proxy health endpoint**: an HTTP `/healthz` for load balancers and Kubernetes probes, instead of opening SSH connections. ([#9](https://github.com/k8shell-io/k8shell/issues/9), [ssh-proxy#37](https://github.com/k8shell-io/ssh-proxy/pull/37), [charts#21](https://github.com/k8shell-io/charts/pull/21))
- **Releases on ghcr.io**: each release's tested images (all platforms, with signatures and SBOM attestations) and chart are published on ghcr.io; the 2.x quickstart installs from there without registry credentials. ([#18](https://github.com/k8shell-io/k8shell/issues/18), [api-server#105](https://github.com/k8shell-io/api-server/pull/105), [authz#21](https://github.com/k8shell-io/authz/pull/21), [frontend#100](https://github.com/k8shell-io/frontend/pull/100), [identity#56](https://github.com/k8shell-io/identity/pull/56), [idp-github#15](https://github.com/k8shell-io/idp-github/pull/15), [idp-google#5](https://github.com/k8shell-io/idp-google/pull/5), [provisioner#82](https://github.com/k8shell-io/provisioner/pull/82), [session#22](https://github.com/k8shell-io/session/pull/22), [ssh-proxy#40](https://github.com/k8shell-io/ssh-proxy/pull/40), [k8shelld#77](https://github.com/k8shell-io/k8shelld/pull/77), [ssh-shield#9](https://github.com/k8shell-io/ssh-shield/pull/9), [charts#33](https://github.com/k8shell-io/charts/pull/33), [charts#36](https://github.com/k8shell-io/charts/pull/36), [charts#37](https://github.com/k8shell-io/charts/pull/37), [charts#38](https://github.com/k8shell-io/charts/pull/38), [frontend#101](https://github.com/k8shell-io/frontend/pull/101), [idp-github#17](https://github.com/k8shell-io/idp-github/pull/17), [idp-google#6](https://github.com/k8shell-io/idp-google/pull/6))
